THE NOTESBEHIND THE CONNECTIONS

A graph of published metadata. A website that follows its links.

The source is Dischord’s Fugazi Live Series. The goal is to help people discover shows and return to their original archive pages—not to host recordings or replace the archive.

From archive pages to relationships

Python collects public HTML metadata: show IDs, dates, venues, locations, listed opening acts, ordered setlists, and source URLs. It does not request audio, sample files, images, or purchase/download endpoints. Collection checks robots.txt, caches HTML, and delays uncached requests.

Dischord HTML→Show records→Graph JSON→Browser search & Explore

A separately curated catalog supplies stable song IDs, explicit aliases, and first-release album matches. Case, Unicode composition, and whitespace normalize; punctuation and uncertain variants are not silently merged. The archive’s original text remains available.

The JSON graph contains 3,529 nodes and 31,260 edges: 1,049 shows, 159 song/track labels, 1,052 opening-act entities, and hierarchical locations. It preserves 24,562 listed track occurrences, including repeated rows and irregular numbering. Its dates run from September 3, 1987 to November 4, 2002.

Song ← performed — Show — happened_in → City
                       ├─ played_at → Venue
                       └─ opened_by → Listed opening act

Shows, songs, and locations are nodes; connections such as performed and opened_by are edges. Separate directed edges retain the country, subdivision, city, and venue hierarchy. A performance edge also stores its source title and track position.

The deployed site loads the exported JSON and builds browser-side lookup tables. Python prepares the files; no live database is involved in search or Explore. The site is published with the existing Quarto / GitHub Pages workflow.

What the search engine actually does

No cosine similarity, embeddings, LLMs, or remote query service. JavaScript normalizes case and whitespace and looks for known entity names, preferring longer complete names such as “Waiting Room.” Quoted phrases stay together. Exact names resolve to graph entities; unmatched terms fall back to substring checks over a show’s searchable metadata.

For Reclamation Richmond VA, it finds shows connected to that song and shows connected to that city and subdivision, then returns their intersection. A four-digit year narrows the date. Selected entities are explicit filters: every selected entity must connect to a returned show. An ambiguous typed name can match multiple entities; selecting a named suggestion chooses its specific identity.

To find a set with your five favorite songs, search for each song and select its suggestion in turn. Each selection becomes a removable filter. Then add a year range or country if you want. The result contains all five songs—or no shows if the published setlists do not support that combination.

The current interface supports intersections, text/phrase matching, year ranges, region, country, and “with a listed setlist.” It does not interpret free-form instructions, “either/or,” exclusions, or song-order conditions. For example, Waiting Room but not Merchandise is not a supported query instruction. Missing setlists prevent conclusions about whether an unlisted song was actually played.

Each show has a visible Setlist link, a clickable date, and a shareable URL such as this Richmond setlist. The selected show is restored on reload. The detail panel appears beside the list on a wide screen and above it on a narrow screen, with a Back to shows control.

What does the network show?

The network in Explore connects opening acts listed on the same Fugazi bill. It shows one view of the archive's relationships. Search uses the complete dataset to find connections between songs, shows, places, and opening acts.

How to read Explore

Top twenty songs
Count distinct shows containing each release-matched catalog song. Repeated track rows count once for this ranking. Intros, interludes, and unresolved track identities are excluded. Percentages use the selected shows with published setlists as the denominator. The Song region control filters this chart by archive country labels, including shows whose cities have no map coordinates. It intersects the shared year/country scope; the map region selector only changes the map viewport. Following a song into Search preserves its region filter.
The map
Count shows by city and plot derived GeoNames city centers, not venue addresses. Four hundred city records cover 1,025 shows; 19 unresolved locations / 24 shows remain unplotted and are listed. World uses an equirectangular overview; regional maps use uniformly scaled Mercator with modern Natural Earth country borders. Historical country labels remain unchanged. Coordinate matching and provenance.
Opening-act network
Node area represents distinct Fugazi shows listing an act. A link joins two acts listed on the same Fugazi bill; its width represents shared-show frequency. The initial view shows the 32 most frequent acts, with a 64-act option. The unidentified “?” label is omitted. Position has no analytical meaning, and sharing a bill does not establish collaboration or musical similarity.

The same year and country scope applies to all three views. Selecting a song, city, or opener reveals its shows and Dischord links. Co-occurrence is derived from published setlists or bills; it is not a new claim added to the original archive.

What has been checked—and what remains unknown

The base validation passed 23 Python regression tests. All 1,049 collected records matched their cached HTML through the existing parser, and the saved graph matched a fresh rebuild. That is a consistency check, not an independent audit of the parser. A reproducible random sample of 20 live pages returned successful HTML responses with matching show IDs and dates; every URL was not re-crawled.

JavaScript checks compare search and metric results against the original records, preserve repeated performance rows, validate coordinate coverage, and check projection geometry. Browser checks cover filters, selections, source links, and regional-only borders.

There are 97 shows without listed setlists and 69 track labels awaiting identity review. Two source setlists have duplicate or skipped numbering and are preserved as published. Opening-act names may have unreviewed variants. Gazetteer matches are derived enrichment, not manual verification of every location. A show page can exist without an available recording.
